# Direct GitHub installation plan

Status: implemented. Generated `dist/` is included in the distribution change;
freshness, Git installation and platform validation are recorded below.

## Decision

Track generated `dist/` alongside TypeScript source for this project's intended
GitHub distribution. An authenticated Git installation can then consume the
existing JS entry points and generated declarations without a compiler or Deno
on the consumer's machine.

Keep `dist/` generated by the current pinned build. Commit source and output
together. Source maps/declaration maps continue to reference the tracked `src/`
files. `.build/`, dependencies and package archives stay ignored.

Recommend pinning consumers to an immutable commit or release tag. `#main` is
also usable, with the consumer lockfile capturing the resolved commit.

```sh
npm install "git+ssh://git@github.com/mcgrue/crustacean-sprite-lib.git#<commit-or-tag>"
```

The repository is private; the consumer's Git credentials must have access.
Registry publication remains deferred. The existing npm `files` and `exports`
fields already describe the generated package contents.

## Implementation

1. Remove the `dist/` ignore entry; generate and stage JS, declarations and maps
   using the existing pinned build.
2. Enforce LF for generated text/map files across Windows/Linux. Preserve the
   byte-exact fixture rules.
3. Add a CI gate that builds in a clean checkout and rejects any difference
   between generated output and the committed `dist/`, including newly emitted
   files. Keep the existing semantic/browser/package gates.
4. Add a new integration test installing from a clean Git checkout into an
   isolated consumer, then importing all four package entry points and checking
   public types. No compiler should run during that install. Existing tests stay
   untouched.
5. Update usage instructions and validate Windows/Linux before committing and
   pushing the distribution change.

Expected cost: generated files increase diffs and must be refreshed whenever
source/compiler changes. CI makes that upkeep explicit and catches stale output.

Git installation and prepare-script behavior:
[npm install documentation](https://docs.npmjs.com/cli/v11/commands/npm-install/).

## Verification

- Windows and Linux: all 89 unit, conformance, browser, package and Git-install
  tests pass with Node 22.20.0 and Deno 2.9.5.
- Normal Git installation also passes with Node 24.10.0 on both platforms;
  consumers import all four entry points and pass strict NodeNext/Bundler type
  checks without an installation build hook.
- All 44 generated artifacts match byte-for-byte across platforms. The freshness
  gate passes against the Windows Git index and a clean Linux HEAD.
- Existing tests and byte-exact source fixtures remain unchanged. Registry
  publication and release tags remain deferred.

# HUMAN QUESTIONS

None required for this recommendation. Default: tracked output on `main`, with
consumer versions pinned by commit. Release tags can be added when requested;
creating a release or publishing to npm is a separate action.
